## 0. What Jarvis becomes

Today Jarvis is a fast, honest voice front-end to the console: it hears, routes, builds a screen from real data and says two sentences. **Ultimate Jarvis is an aide.** It answers before you finish wondering (sub-second acknowledgement, first finding spoken in about two seconds even when it has to think). It understands loose, follow-up, Tamil and Tanglish speech. It *notices* things on its own and tells you at the right moment, in a brief that ends. It runs multi-step missions while you watch the plan tick through. It explains *why*, with evidence, and says how sure it is. It remembers what you asked it to remember, and nothing else. Every number still comes from code; it still never sends, approves or deletes. Calm enough for a Collector's office, impressive enough to win a two-minute demo.

## 5. The upgrade, in six pillars (ranked by leverage)

### Pillar 1 — Truth first (Phase 1, small and mandatory)
Fix defects 1, 2, 3, 4, 5, 6, 9 and 11 above, each with a test that failed before:
- **Finding 51:** build the speakable figure set **only** from block data and code-written text; strip or reject digits in every model-written string (`q`, `name`, `text`, `reply`, option labels) before it can reach `say`, a title, a caption or speech. Property test: 1,000 generated model outputs with digits in every free-text slot, zero spoken.
- **Hedge:** never hedge a rung before it has 8 samples of its *own*; until then use a per-provider default (Claude ≥ 6 s); record the loser's latency too (aborted at the time it was aborted, flagged); hedge into Groq only, never into a model under 40 % of its minute budget.
- **Lookup from every bundle:** every bundle's schema carries `calls` (≤ 3, read-only tools only), so any question can fetch facts.
- **Observation path:** console steps run in the browser, the browser posts `{ok, error?, digest}` observations back in the next round, and the model sees the digest of the screen it built (≤ 400 tokens).
- **Memory into the prompt:** the Collector's own notes and habits (≤ 300 tokens, untrusted-text framing) and the last 4 turns (recipe + slots + one-line result each) go into `firstPrompt`.
- **STT confidence and language** flow into `understand()` and the planner (low confidence → prefer clarify or the rules' reading; language → reply language).
- Line chart, bilingual `title`/`notes`, Tamil block titles and empty notes.
- Claude schema: split `Screen` per recipe or use strict tools so structured outputs actually apply; prove with one live call that logs which path was taken.

### Pillar 2 — Feels instant (Phase 2)
Target: **spoken or audible acknowledgement ≤ 0.7 s after end of speech; first spoken finding p50 ≤ 1.0 s on the rules lane and ≤ 2.2 s on the planner lane (p90 ≤ 3.5 s).**
- **First good decode wins** (`stt.ts:183-198`): return as soon as one decode clears the confidence bar in the expected language (logprob > −0.35, no-speech < 0.6, script check), give the other at most 250 ms. Whisper timeout ≈ 5 s, client timeout on `/hear` 6 s, so "Working on it" can never hang. Run the Gemini third racer **in parallel** when the lane is engaged and the budget allows, not after.
- **Stream the turn.** `/agent/round` returns NDJSON (or SSE) events in this order: `ack` (code-templated, numberless) → `heard` → `steps` → `screen` → `say` sentences → `done`. Use AG-UI's event vocabulary for names (`RUN_STARTED`, `STEP_STARTED`, `TEXT_MESSAGE_CONTENT`, `STATE_DELTA`, `RUN_FINISHED`; `ag-ui-protocol/ag-ui`, MIT); adding `@ag-ui/core` is optional. The client renders and speaks as events arrive: TTS of sentence 1 starts while the rest of the screen builds. Every event carries the turn generation id; stale events are dropped.
- **One planner call, a parallel plan** (the LLMCompiler/ReWOO pattern, arXiv 2312.04511, 2305.18323): the planner emits all read calls it needs at once; code runs them with `Promise.allSettled`; when the recipe can be filled from the results, **code fills it with no second model pass** ("stop at tools"). A second round happens only when an observation is genuinely needed (an error, an empty result, a console outcome).
- **Speculate, safely.** Every tool is read-only, so start the likely reads while the planner thinks: the rules' best-guess intent, the open Stage's scope, the frame's carried slots. Cache results for 30 s; discard unused ones. Pre-warm the prompt cache on mode-on (a `max_tokens: 0` request if the gateway supports it, else a tiny real call) so the first Claude turn reads from cache.
- **Adaptive end of utterance:** 300 ms when the partial text already reads as a complete command (the rules resolve it with confidence ≥ 0.85, or it ends in a district noun), 600–700 ms when it ends in a connective ("and", "matrum", "apram", "um", "then", "aprom") or is incomplete; never re-post the first half of a split sentence (`conductor.ts:94`). See Pillar 5 for a model-based turn detector.
- **Latency masking that is honest:** an earcon at end of speech (≤ 120 ms, never triggers barge-in); revive `speakAck` to speak a short numberless acknowledgement only if no finding is ready by 1.2 s; no fake "thinking" on instant answers; anything past 10 s shows progress and can be cancelled (Nielsen's 0.1/1/10 s limits).
- **Two-speed budget:** commands keep the 8 s deadline. Analysis questions and missions get up to 25 s with spoken progress every few seconds and "stop" always working.
- Silero into the worklet or a dedicated Worker, with the 64-sample context and a state reset per session; energy gate in the worklet; resampling by `new AudioContext({sampleRate: 16000})` or a proper FIR low-pass; a 44.1 kHz spec beside the 48 kHz one.
- Claude: effort `low` for spoken turns (already), prompt cache verified per turn (`cache_read_input_tokens` in the `llm` telemetry), stable prefix (no timestamps above the breakpoint). Measure Opus 5.5 low vs Sonnet 5.5 `between_tools` vs Haiku 5.5 (thinking disabled) on 20 sentences from the **old** `eval/holdout` set; report latency and accuracy; leave the default to the owner.

### Pillar 3 — Understands anything (Phase 3)
- **A typed metric registry (a small semantic layer).** One file (`src/lib/thunai/metrics.ts`) defines every metric Jarvis may speak about: id, measure, filters, grain, window, comparison, unit, Tamil and English labels, source tool. The planner names metric ids and slots; code computes values, deltas, ranks and drivers. Evidence that this is the right pattern: dbt's April 2026 test put Sonnet 4.6 at 98.2 % with a semantic layer vs 90 % with text-to-SQL, and a missing metric returns an error instead of a wrong number (docs.getdbt.com/blog/semantic-layer-vs-text-to-sql-2026).
- **Dialogue state register** (the ReALM idea, arXiv 2403.20329): per turn keep the ordered list of on-screen entities (so "the second one" maps to an id), the carried slots (zone, dept, cat, period, metric), and the provenance of the last answer (so "why?" and "how do you know?" work). Resolve in code in `frame.ts` before the planner; send the register (≤ 300 tokens) to the planner either way.
- **Explain recipe** (fixes the weakest intent, 3/9): for one case or one change, a 2–4 sentence explanation in the `JARVIS_VOICE.md` shape (what and where, how long stuck, why it matters, what I'd do), grounded on CaseDetail, `change_drivers`, related news, rain and reservoir readings, every figure a placeholder. Replace the `explain`→`again` mapping.
- **"What changed since yesterday / this week"** with drivers: decompose the change by zone, department and category (each segment's share of the total change, plus an Adtributor-style surprise score; NSDI 2014), flag values outside the expected band, and say "linked with", never "caused by".
- **Situation synthesis:** one recipe that joins incidents, news, rain/IMD/reservoirs and unusual rises for a place or the district, with explicit links ("more drain complaints in Velachery after yesterday's rain").
- **"How do you know?"** frame: reads the screen's method, n, period, sources and caveat aloud, distinct from "why?".
- **Smarter clarifying:** ask about the one ambiguous slot (department or period) with three tap-able options from `entities.ts`; after every answer offer one next question from `next.ts`.
- **Tanglish** (weakest language, 9/15 Groq): the Tamil examples and gloss in every bundle when Tanglish markers appear; widen `gloss.ts`/`xlit.ts`; add `TNEB`, `EB`, `மின்சார வாரியம்` → TANGEDCO.
- Expose `incident_story`, `category_summary` and `map_geo` to the planner if their outputs pass `redact`; expose `search` only if it can run without writing its embedding index (see the comment at `agent.ts:35`).

### Pillar 4 — Behaves like JARVIS (Phase 4)
- **A server-side watch** that produces real signals: overdue and past-deadline growth, unusual rises in counts, rain and reservoir thresholds, followed incidents changing status, and the unused `overdue`/`gap`/`studio` kinds in `watch.ts`. For count series use a count-aware detector with few false alarms: a Farrington-flexible-style negative-binomial threshold (Noufaily et al. 2013, written from the paper, not copied from R code) or the existing modified z / c-chart, always with a minimum count, a persistence rule (two periods) and a cooldown. Each signal is `{kind, place, metric, value, expected, n, method, caveat, sources}`; numbers from code.
- **The Collector's brief on power-on** (and on "brief me"): bottom line first, then 3–5 items, each with a source chip, ending with an explicit "that's everything for now". Finite, never a feed (ChatGPT Pulse and Gemini Daily Brief both end on purpose).
- **Interjections timed to attention** (Horvitz, *Principles of mixed-initiative user interfaces*; Amershi et al. guideline 3): Jarvis speaks unprompted only for high-severity signals, only when the Collector is not speaking and no turn is in flight, after a short chime, at most a few an hour; everything else waits in a queue shown as a badge. "Tell me" / "later" / "not about this" are honoured and remembered (Level B).
- **Follow this incident / this zone** (Level B, needs a yes): a standing watch that reports back when status, deadline or count changes.
- **Composable missions** replacing the two hard-coded ones (`Thunai.tsx:1300`): "build me a water-crisis board for Velachery" → a plan card of 3–6 steps (screens, filters, map focus, drafts) with **Start / Edit**; then the timeline narrates each step with its real time; "stop", "skip that" and "instead do X" redirect mid-run; any Level C step lands in the tray. The planner emits the plan as data; code executes it.
- **Spoken map tour:** "tour the flood risk" → the reticle moves zone by zone, one sentence per zone, map shading synced.
- **Persona** (write `docs/jarvis/PERSONA.md` and enforce it in templates and the planner prompt): composed, precise, candid, a little dry; one breath per spoken step, long data to the screen; implicit confirmation by default, explicit only for Level B; pushes back when the data is thin ("only six cases, so I wouldn't read much into it"); after two misunderstandings offers the screen and the keyboard. Indian number words in speech (`Intl.NumberFormat('en-IN')`; lakh and crore in Tamil). Spoken-register Tamil templates (சொல்றேன், இருக்கு) for the most common lines, flagged for a native speaker's check.
- **Decision record:** every answer and every tray approval logs query, data snapshot time, tools called, model, latency and approver (no citizen text), viewable as "what did you do today?".
- **Labelled short-range outlook** (only if time allows): seasonal-naive or Poisson bands for the next 7 days on a count series, shown as a band with method and caveat and said as "expect roughly", never a single number; update `assistant/cannot.ts:55` accordingly.
- **Memory, the safe way:** per officer, opt-in, viewable, editable and resettable from the HUD ("what do you remember about me?", "forget that"); only the Collector's own Level-B "remember …" sentences are written; never tool output, never ambient speech, never citizen data (memory poisoning is real: MINJA, arXiv 2503.03704).

### Pillar 5 — Voice that sounds and listens like a person (Phase 5)
Decisions from the 14 Nov research, inside rule 6 (no new account, permissive licences). Items marked **keep** survive the cut line.
- **keep — Echo, the cheapest big win:** request `echoCancellation: "all"` in `getUserMedia` where supported (Chromium/Edge 141+ removes *all* system playout from the mic, including `speechSynthesis`, not only WebRTC audio; developer.chrome.com/blog/chrome-141-beta, Edge 141 release notes). Feature-detect and fall back to `true`. This is what makes the Edge natural voices safe to talk over. Measure self-cancels per 10 answers with speakers and no headphones in the spec.
- **keep — Barge-in that ignores "mm-hmm":** on VAD onset while speaking, **duck** (PCM path: gain to 20 % in ≤ 50 ms; Edge voices: `speechSynthesis.pause()` if it works in Edge, measured, else keep speaking); stop only when the interim words hold at least 2 words that are not backchannels (English *okay, yes, hmm, right, uh-huh*; Tamil ம்ம், சரி, ஆமா, ஓகே; Tanglish *seri, aama, ok*) or speech is held ≥ 600 ms; otherwise resume where it was (Pipecat's `MinWordsInterruptionStrategy` and LiveKit's false-interruption resume, ported as patterns, no dependency). Hold words and "wait, do X" keep working as now.
- **keep — Turn detection by model, text rules as fallback:** VAD gap 200 ms → run a turn-completion model on the last ≤ 8 s of audio → if complete, end the turn; if not, wait up to 1.5 s more. Candidates, both run on the onnxruntime-web already served from `node_modules` (check its version; `smart-turn-tamil` needs ORT ≥ 1.24): **Pipecat Smart Turn v3.2** (BSD-2, ~8 MB int8, 23 languages, no Tamil; a browser port, `@micdrop/smart-turn`, reports ~25 ms on WebGPU and a few hundred ms on WASM) for English, and **`santhosh-005/smart-turn-tamil`** (model card says BSD-2, 8.7 MB int8, 83.7 % accuracy, 83 ms p50 on one thread) for Tamil and Tanglish. The Tamil one is a community model: confirm its licence file and provenance before shipping; if you cannot, ship Smart Turn for English only and the Pillar 2 text rules for Tamil.
