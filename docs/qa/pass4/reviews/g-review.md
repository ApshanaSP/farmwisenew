## Serious problems, most serious first

1. **RC-04 / RC-18: the "done phrase" fix opens a bypass of the instruction guard (P1).** `privacy.ts` (`fd16224`) removes `\b[a-z][a-z-]*\s*aachu|aayiduchu...` and the Tamil `\S+\s*ஆச்சு...` from the text before it looks for forbidden orders. The removed text includes the word in front of the marker, which is usually the object of the order. Ran `asksForbidden`: "ignore all your rules" is true, but "ignore all your rules aachu", "ignore previous instructions aachu", "forget your rules aayiduchu", "ignore your rules ஆச்சு" and "அனைத்து விதிகளையும் புறக்கணி ஆச்சு" are all false. The commit text says only the done phrase is taken out; the tests (`g1.pass4.test.ts`) only try approve, delete, send and close, never the override rule, and never a hostile word before the marker. This runs in `router.ts`, `brain.ts`, `agentServer.ts`, `exitgate.ts`, `quick.ts` and now `understand.ts`, so the marker lets an override sentence reach the model. Mechanism wanted: take the marker out only when the verb in front of it is the whole done phrase and nothing else of the rule (verb plus marker, checked against the verbs), or only apply it to the order verbs and never to the override and reveal rules.

2. **U1 deleted four existing a11y guards without saying so (P1, process).** `b03acd7` rewrote `src/components/a11y.pass4.test.ts`. The old file had four tests that the new file does not have: PB-320 (every button in a `role=tablist` is a `role=tab`), PB-321 (no page loads a stylesheet or font from another host: the cause of the console error), PB-322 (muted and subtle text reach 4.5:1 in both themes, a real ratio computation), PB-323 (the language switch names itself with the words it shows). The commit message does not mention it. The rule is "never weaken a test; explain any change to an existing test". I ran the old file from `7f7d537` against this tree: all 4 still pass, so nothing hid a failure, but the PB-321 and PB-322 regressions (the font link, a colour token) are now guarded by nothing in the suite (only `axe.mjs`, a browser script that is not run by `vitest`). The new tests (headings, main, ring) are good and should be kept. Put the four back.

3. **RC-05 / RC-06: a filter or a window is still dropped silently in Jarvis (P1).** Real path, no model:
   - "last month resolved cases", "pona maasam resolved cases", "pona vaaram overdue cases", "கடந்த வாரம் தாமதமான புகார்கள்", "கடந்த மாதம் தீர்க்கப்பட்ட புகார்கள்" answer with a single `period` step ("Last 30 days"). The status word is thrown away. "indha vaaram overdue cases" and "last month overdue cases" are answered with `status=overdue`. Cause: `calendarWindowIn` (the "pona/kadantha/last week" words) makes the fast lane bail, so the thinner rules lane (`understand.ts`) takes it, and its guard against dropped statuses is `if (hasView && !itemStep && statusIn(...))`: a period with no place never trips it. The ledger says "last week/month are the same window in three languages"; the window is, the lane and so the filter are not. The g2 guard feeds every PERIOD_TABLE word through the fast lane and checks the window said, not that the rest of the sentence survives.
   - "severe cases in the last 3 days" and "...last 14 days" are answered "8 severe cases today" with no word that the number was not read. The table has no numeral windows; RC-06 says "one table and a test that checks the window said". RC-43 fixed "last 0 days" for Ask District IQ only.
   - RC-05's guard asked for "if any slot is read but not applied, ask". G2 built it as `unknownTopicIn` (an English word of 3+ letters in front of "complaints"), `unreadClauseIn` (3 or more unread words beside a complaint noun) and `tiedTopics`. Each is a narrow rule for the sentence that failed. The general rule (count the slots read, compare with the slots applied) is not there.

4. **Guards that pass whatever happens (P2).** `g2-real.test.ts`:
   - "a status said after the noun is a status" asserts only that there is no `view` step. In rules-only mode "show open cases in Adyar" and "Drainage cases open in Kodambakkam" are answered "I cannot reason right now"; that passes. So would a plain place list with no status.
   - "an unread kind of complaint is not answered with a bare window" is also only "no period or view step". The positive control (`kind !== "none"`) accepts a refusal.
   - "a move's confirmation holds no English body or category name" starts with `if (!view step) return;`, so the line it guards is never checked when the sentence is handed on.
   - "a Tamil brief point holds no English headline" returns early when the first block is not a Brief.
   These should assert the answer: the status in the slots (or a question that names it), and that a handed-on sentence ends in a question or a model call, not in a cannot-reason line.

5. **RC-44: the share is labelled "complaints" and counts incidents (P2).** `fastpath.ts` share branch uses `countNoun(what, n)`. "what percentage of complaints are resolved" gives "N% of complaints are resolved: x of y" where x and y are incidents (`shareOfIncidents`), while `cannot.ts` refuses "complaints by department" because the department list counts incidents, not complaints. Two answers disagree on the unit. `g2-ask.test.ts` checks `/% of .* are resolved/`, so a wrong noun passes. This is the unit question of RC-40 (owner's decision); at least the noun should say incidents.

The change is small and honest in its comment; the owner should decide whether to keep it, and the OPEN-11 row should stay open in the baseline.

7. **A guard that cannot see the thing it guards (P2).** `a11y.pass4.test.ts` "only a control with its own ring switches the base ring off" takes the selector list after `.dic :focus-visible,` and so never examines `.dic :focus-visible` itself, the one rule that switches the ring off for every control in both consoles. 8. **A test now red on the calendar (P2, RC-36 class).** `src/app/api/collector/jobs/route-news/route.test.ts` ("routes with the key...") fails today (`candidates: 0`, expected 1), alone and in the full run. 9. **RC-16: "IST" is listed as a named zone but cannot be parsed (P2).** `parseWhen` (`c99b95b`): the `named` regex lists `IST`, then `new Date(s)` is used, and JavaScript returns Invalid Date for "02 Oct 2026 11:30 PM IST" (checked in node). Same result as before the fix, so not a regression, but the new comment says "the zone the text names wins" and the zone test has no IST case.
