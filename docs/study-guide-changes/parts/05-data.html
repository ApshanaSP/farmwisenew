Chapter 5Data: ward to taluk, and the 28 November round

In one line

Each of the 200 GCC wards is now placed in its revenue taluk from official TNGIS revenue-village boundaries, checked village by village against the Chennai Collectorate's list.

5.1 Where the ward to taluk mapping comes from

  1. Ward side: the console's own ward polygons, a DataMeet community copy of the GCC wards (2011-era numbering in several zones). No official ward-to-taluk table is published anywhere.
  2. Taluk side (official): revenue village polygons from TNGIS (Tamil Nadu Geographical Information System, run by TNeGA), public WFS layer tngis_basemap:basemap_revenue_village, each with its taluk.
  3. Checked against the Chennai District Collectorate's list of 17 taluks and their villages (chennai.nic.in/revenue-administration). 136 of 140 TNGIS villages matched the Collectorate's taluk; Kolathur, Peravallur and Siruvallur moved to the Kolathur taluk formed in 2024.
  4. Overlay: each ward is sampled on a 25 m grid; each point is placed in a village; the ward's taluk is the taluk holding the largest share of its area. Shares and flags (a near tie, a ward whose official number lies in another taluk) are kept.

Files: district_intel/reference/ward_taluk.csv (one row per ward), ward_taluk_villages.csv, ward_taluk.meta.json; built by scripts/build_ward_taluk.py. The pipeline only reads the CSV.

Be honest about

TNGIS's terms do not allow publishing derived data without TNeGA's approval, and the CSV is in the repository the hourly GitHub run reads. Mention it if asked about licensing.
